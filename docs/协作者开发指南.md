# 协作者开发指南（怎么一起改这个项目）

> 线上仓库：**https://github.com/guli504/doc-format-tool**（公开，默认分支 `main`，GitHub Pages 自动部署）
> 本指南写给：想一起改这个工具的团队成员 / 协作者。

---

## 一、先搞清楚：网上仓库里有什么

协作者 `git clone` 下来的是**全部源代码**：

```
doc-format-tool\
├─ index.html            页面骨架（左面板 / 中间预览 / 顶栏）
├─ css\app.css           全部样式
├─ js\
│  ├─ constants.js       默认参数（字号 / 行距 / 模板 / 标点）
│  ├─ knowledge.js       规范知识库（数字与单位）
│  ├─ engine.js          核心引擎（解析 / 整改 / 检测）
│  ├─ ooxml.js / render.js / legacy-doc.js / store.js
│  └─ app.js             界面交互
├─ js\vendor\jszip.min.js
└─ README.md
```

注意：仓库里**没有** `build\`、`test\`、`发布\`（打包脚本、测试、单文件成品在项目所有者本地）。

---

## 二、两种合作方式，先选一种

| 方式 | 适合 | 权限 | 改动怎么上线 |
| --- | --- | --- | --- |
| **A. 受邀协作者** | 小团队 / 同门 / 固定搭档 | 直接往 `main` 推 | `git push` 后线上**自动更新**（约 1 分钟） |
| **B. Fork + Pull Request** | 外部任何人 / 不固定贡献者 | 只能改自己的副本 | 发起 PR，仓库所有者审核后合并 |

---

## 三、方式 A：受邀协作者

### 第 1 步：被邀请（仓库所有者 guli504 操作）
1. 打开 `https://github.com/guli504/doc-format-tool` → **Settings**（齿轮）→ 左侧 **Collaborators** → **Add people**
2. 输入协作者的 **GitHub 用户名** → 发送邀请
3. 协作者在自己的 GitHub 通知里点 **Accept invitation**

### 第 2 步：协作者第一次配置（电脑上）
需要装：**Git**（https://git-scm.com/download/win），会用 **VS Code** 更好。

```bash
# 把项目克隆到本地
git clone https://github.com/guli504/doc-format-tool.git
cd doc-format-tool

# 设置自己的身份（第一次推送前必须，否则提交人不明）
git config user.name "你的名字"
git config user.email "你的GitHub邮箱"
```

### 第 3 步：改 → 提交 → 推送（线上自动生效）

```bash
# 改代码（js\ css\ index.html）
# 改完查看改了什么
git status

# 提交
git add -A
git commit -m "说明你改了啥，例如：知识库新增 Mb 单位"

# 推送到线上 → GitHub Pages 自动重新部署，约 1 分钟后生效
git push
```

> 线上是"多文件版"，**改完 push 就上线，不需要本地打包**。
> 需要给别人的"离线单文件版"（一个 HTML 拖走就能用）由仓库所有者用 `发布\重新打包.bat` 生成后再推一次。

---

## 四、方式 B：外部贡献者（Fork + Pull Request）

1. 打开仓库页面 → 右上角 **Fork**（复制一份到你账号下）
2. 克隆你自己的副本 → 改代码 → 推送
3. 回到原仓库页面 → **Pull requests** → **New pull request** → 说明改了什么
4. 仓库所有者审核、合并后，线上自动更新

适合给项目提建议 / 修 bug 的人，不需要任何信任关系。

---

## 五、协作者改代码的注意点（防坑）

1. **只改源代码**：`js\` `css\` `index.html`。别去改线上没有的、也别把大文件塞进仓库。
2. **编码**：`.js/.css/.html/.md` 一律 **UTF-8**。不要用记事本另存成"ANSI"。
3. **动手前先 pull**：`git pull` 拉最新，避免和别人改冲突。
4. **一次只改一件事**，提交信息写清楚，方便回滚。
5. **改动大先备份**：复制一份文件夹再改。
6. **改 JS 顺手升版本号**：改 `js\constants.js` 顶部的 `VERSION`（如 `1.2.0`→`1.3.0`），并同步把 `index.html` 里的 `?v=120` 改成 `?v=130`。否则别人浏览器可能用缓存的旧文件看不到你的改动。
7. **遇到冲突**：`git pull` 报冲突时，VS Code 会标出冲突段落，两边内容都在，手动保留需要的那部分再提交。

## 六、协作者想跑自测 / 打包（可选）

仓库里暂时没有 `test\` 和打包脚本。如果你（协作者）也想：
- **跑自动化测试**：让仓库所有者把 `test\` 目录也提交进仓库，然后本地装 Node.js，浏览器打开 `test\engine-test.html` 看是否"全部通过"。
- **生成离线单文件版**：让仓库所有者把 `build\build-single.js` 和 `发布\重新打包.bat` 也提交进来，配合 Node.js 就能自己打包。

需要的话，直接跟所有者说"把开发工具也放进仓库"，他会同步过来。

## 七、常用速查

```bash
git pull                 # 拉最新
git status               # 看改了什么
git add -A               # 暂存全部改动
git commit -m "说明"     # 提交
git push                 # 推上线（A 方式直接生效；B 方式推自己的 fork）
```

| 想改什么 | 改哪个文件 |
| --- | --- |
| 数字与单位规范 | `js\knowledge.js` 的 UNITS / CATEGORIES |
| 默认参数（字号/模板/标点） | `js\constants.js` 的 DEFAULT_PARAMS |
| 按钮文案 / 标题 / 说明 | `index.html` |
| 颜色 / 圆角 / 动画 | `css\app.css` 顶部的 `:root` |
| 整改逻辑 | `js\engine.js` |
| 预览效果 | `js\render.js` |
| 按钮行为 | `js\app.js` |

## 八、上线机制说明（给协作者提个醒）

- 推送到 `main` 后，GitHub Pages 会自动重新部署，**约 1 分钟生效**。
- 如果改了 10 分钟线上还没变：到仓库 **Settings → Pages** 看一眼构建状态；偶尔构建会卡住，点一下 **Deploy** 或再随便推一次空提交触发即可。
