# 怎么让别人也能用？—— 三种方案（挑一个就行）

> **先说清楚为什么别人打不开：**
> 你现在看到的 `http://127.0.0.1:19387` 是**你这台电脑自己的本机地址**（127.0.0.1 永远只指向"本机"），
> 而且那是 DSH 软件自己的界面地址，跟这个整改工具没有关系。
> 别人电脑上既没有这个地址，也访问不到你的电脑，所以必然打不开。
>
> 要让别人用，本质只有两条路：**要么把文件发给他**，**要么把工具放到公网上**。下面三种方案按"省事程度"排列。

---

## 方案 A：单文件版 —— 最省事，适合发给同事 / 客户（推荐先试这个）

工具已经被打包成**一个 HTML 文件**：`发布/文档格式整改工具.html`（约 315 KB）。

**怎么用**

1. 把这个 HTML 文件直接**发微信 / 发邮件 / 拷到 U 盘**给对方；
2. 对方**双击打开**（如果默认浏览器不是他想要的，右键 →「打开方式」→ Chrome/Edge）；
3. 完事。不用装软件、不用联网、不用配置，打开就能拖文档进去整改。

**优点**

- 零门槛，对方什么都不用装；
- 完全不联网，文档只在对方自己电脑上处理，最安全；
- 你可以随便改名（比如改成「文档排版一键整改.html」），一样能用。

**小提示**

- `发布/启动工具.bat` 是给你自己用的启动器：双击它就会用默认浏览器打开工具（不用去找那个 HTML）。
- 想做"软件感"更强：右键那个 HTML →「发送到」→「桌面快捷方式」，跟装了个软件一样。

## 方案 B：放到 GitHub 上 —— ✅ **已经发布完成，直接用网址**

把这个网址发给任何人（微信、QQ、邮件、群里）就能用：**手机、平板、别人的电脑都行**，对方不用装任何东西。
- 仓库地址（可以看源码）：<https://github.com/guli504/doc-format-tool>
- 以后改了内容想更新：双击 `发布/更新线上网站.ps1`，约 1 分钟后线上自动生效
- 再强调一次隐私：托管到 GitHub 的只是**工具网页本身**；每个人的文档仍然只在他自己的浏览器里处理，不会上传到 GitHub

下面是完整的原始步骤（已经执行完毕，留作记录，或在你要换账号 / 换仓库名时参考）。

---

放上去以后，所有人都能用 `https://你的用户名.github.io/doc-format-tool/` 这个网址访问。
**注意：托管到网上的是"工具网页本身"，不是别人的文档**——每个人的文档仍然只在他自己的浏览器里处理，不会上传到 GitHub，隐私和安全不受影响。

### 第一步：注册 / 登录 GitHub

打开 <https://github.com> ，没有账号就注册一个（免费）。

### 第二步：新建一个仓库

1. 打开 <https://github.com/new> ；
2. **Repository name** 填：`doc-format-tool`（也可以叫别的，名字会出现在网址里）；
3. 选 **Public**（公开。免费账号的 Pages 功能只支持公开仓库；工具本身只是网页代码，公开没有隐私问题）；
4. **不要**勾选 "Add a README file"、"Add .gitignore"、"Choose a license"；
5. 点 **Create repository**。

### 第三步：把文件传上去（二选一）

**方式 1：网页拖拽上传（不用装任何东西）**

1. 在刚建好的仓库页面，点 **uploading an existing file** 链接；
2. 打开电脑上的 `发布\网站版` 文件夹，**Ctrl+A 全选**里面的 `index.html`、`css`、`js`、`README.md`；
3. 把这几个文件/文件夹**拖进网页的上传框**（文件夹会被保留目录结构）；
4. 下面 Commit changes 点一下 **Commit changes**。

**方式 2：用我准备好的脚本自动推送（推荐，以后改东西再推一次就行）**

1. 右键 `发布\一键推送到GitHub.ps1` → **使用 PowerShell 运行**；
   （如果右键没有这一项：开始菜单搜 PowerShell → 打开 → 输入
   `powershell -ExecutionPolicy Bypass -File "D:\deepseek harness\doc-format-tool\发布\一键推送到GitHub.ps1"` 回车）
2. 按提示输入你的 GitHub 用户名（例如 `guli504`）和仓库名（回车 = doc-format-tool）；
3. 首次会**弹出浏览器让你登录 GitHub**，登录一次以后就不用再登了；
4. 脚本会自动 `git init → commit → push`，成功后还会帮你打开开启 Pages 的页面。

### 第四步：开启 Pages（生成网址）

1. 打开 `https://github.com/你的用户名/doc-format-tool/settings/pages`；
2. **Source** 选 `Deploy from a branch`；
3. **Branch** 选 `main`，右边文件夹选 `/ (root)`，点 **Save**；
4. 等 1～2 分钟（第一次部署需要时间），刷新页面会看到绿色提示；
5. 别人就能用这个网址打开了：

```
https://你的用户名.github.io/doc-format-tool/
```

### 常见问题

| 情况 | 处理 |
| --- | --- |
| 打开网址是 404 | 再等 1～2 分钟；确认 Source 是 `main / (root)` |
| push 时报 `repository not found` | 仓库还没建，或用错了用户名/仓库名；先去 <https://github.com/new> 建好再重试 |
| 国内访问 github.io 很慢 | 见下方"国内备选" |
| 网址太长/不好记 | 可以在浏览器里收藏，也可以用短链接服务；或买域名绑定（Pages 支持自定义域名） |

### 国内备选（如果 GitHub 打不开）

| 平台 | 说明 |
| --- | --- |
| **Netlify Drop** | 打开 <https://app.netlify.com/drop>，把 `发布\网站版` 整个文件夹拖进去，几秒后就给你一个可访问网址（建议注册免费账号长期保留） |
| **Vercel** | <https://vercel.com> 注册后 New Project → 选择 GitHub 仓库或直接拖文件夹 |
| **Gitee Pages（码云）** | 国内访问快，但需要实名认证，且免费版每次更新要手动点"更新" |
| **Cloudflare Pages** | 免费、稳定，需要注册账号 |

## 方案 C：局域网共享 —— 同一个办公室/同一个 WiFi 里用，零配置

适合"办公室里几个人一起用"，不用上网、不用注册。

1. 双击 `发布\局域网共享.bat`；
2. 窗口里会打印出类似这样的网址（可能有多个，任选一个）：

```
http://10.168.169.77:8899/
```

3. 把这个网址发给**同一个 WiFi / 同一个局域网**里的同事，他们用浏览器打开就能用；
4. 想停止共享：在那个窗口按 **Ctrl+C**，或直接关掉窗口。

**注意事项**

- 第一次运行如果弹出「Windows 安全中心」防火墙提示，**勾选"专用网络"并点"允许访问"**；
- 你的电脑要开着、那个窗口要开着，同事才能访问；
- 同事的文档仍然是在**他自己的电脑上**处理的（页面只是从你这里加载），不会跑到你的电脑上；
- 如果提示端口被占用，换一个：在窗口里执行 `powershell -ExecutionPolicy Bypass -File .\局域网共享.ps1 -Port 8900`。

## 三种方案怎么选

| | 方案 A 单文件 | 方案 B GitHub 网址 | 方案 C 局域网 |
| --- | --- | --- | --- |
| 上手难度 | ★ 最简单 | ★★★ 需要注册 GitHub | ★★ 双击即可 |
| 别人需要装东西吗 | 不需要 | 不需要 | 不需要 |
| 别人怎么拿到 | 你发文件给他 | 直接打开网址 | 同一网络打开网址 |
| 需要联网吗 | 不需要 | 需要 | 局域网内即可 |
| 适合场景 | 发给 1～几个人 | 公开分享、长期使用 | 办公室内几个人 |
| 你要一直开着电脑吗 | 不用 | 不用 | 要 |

**建议**：先用方案 A 发给身边的人（现在立刻就能用）；想让更多人用、想要一个固定网址，再做方案 B。

## 附：发布文件夹里都有什么

| 文件 / 文件夹 | 用途 |
| --- | --- |
| `文档格式整改工具.html` | **单文件离线版**，发给别人就用它 |
